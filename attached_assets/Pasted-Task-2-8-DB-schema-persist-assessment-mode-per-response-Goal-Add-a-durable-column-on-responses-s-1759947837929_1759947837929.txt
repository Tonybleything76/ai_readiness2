Task 2/8 – DB schema: persist assessment mode per response

Goal
Add a durable column on responses so each submission records whether it used the Free (25Q) or Full (90Q) question set. This will power analytics, upgrades, and reporting.

Current State
- Question files + loader are in place:
  /data/ai_readiness_free_25.json  (25Q)
  /data/ai_readiness_full_90.json  (90Q)
  /server/utils/questionLoader.ts   (exports question counts and data)
- Server boots cleanly and logs counts.

Scope
1) Drizzle schema & migration
   - Add enum 'free' | 'full' as assessmentMode on responses.
   - Also add questionCount (int) for resilience and analytics.
   - Add index on (assessmentMode, createdAt).

   Example (TypeScript/Drizzle):
   // server/db/schema.ts
   export const assessmentModeEnum = pgEnum('assessment_mode', ['free','full']);

   export const responses = pgTable('responses', {
     id:          uuid('id').primaryKey().defaultRandom(),
     createdAt:   timestamp('created_at', { withTimezone: true }).defaultNow(),
     orgName:     text('org_name'),
     industry:    text('industry'),
     answersJson: jsonb('answers_json').notNull(),
     pillarScores: jsonb('pillar_scores').notNull(),
     overall:     real('overall').notNull(),
     category:    text('category').notNull(),

     // NEW:
     assessmentMode: assessmentModeEnum('assessment_mode')
                      .notNull()
                      .default('free'),
     questionCount: integer('question_count').notNull().default(25),
   });

   // Add index file if not present:
   export const responsesModeIdx = index('responses_mode_created_idx')
     .on(responses.assessmentMode, responses.createdAt);

2) Migration script
   - Create migration to add the enum, new columns, and index.
   - For existing rows, backfill defaults: assessment_mode='free', question_count=25.

3) Types & repository updates
   - Update any TypeScript types that reference the responses row shape.
   - Ensure the repository/create method expects an assessmentMode and questionCount.

4) Wire-up in server (non-breaking)
   - In the score/submit path (don’t change behavior yet), if request body doesn’t pass a mode, set:
       assessmentMode = 'free'
       questionCount = FREE_COUNT (from questionLoader)
     (This keeps Task 2 safe and shippable. We’ll add real mode selection in later tasks.)

Files to Touch
- server/db/schema.ts (and/or drizzle schema files)
- server/db/migrations/* (auto-generated by drizzle-kit)
- server/storage.ts or server/services/responses.ts (where insert happens)
- shared/types.ts (if you mirror row types)

Acceptance Criteria
- Migration runs successfully.
- New rows inserted after this change contain:
  - assessmentMode: 'free' or 'full' (default 'free' for now)
  - questionCount: 25 or 90 (default 25 for now)
- Existing rows are backfilled with ('free', 25).
- An example insert path compiles and runs (unit test or dev script).

Rollback Plan
- Create a down migration that:
  - Drops index, drops question_count, drops assessment_mode columns, and enum.
- Validate that application still boots with previous schema.

Notes
- Use FREE_COUNT and FULL_COUNT from /server/utils/questionLoader.ts when setting questionCount during insertion once mode is known (future task); for now default to FREE_COUNT.
- No UI or endpoint logic change yet—this task is schema only with safe defaults.
- Keep CSRF, JWT, and other security middleware untouched.
